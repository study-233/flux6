# macOS 核心配置检查记录 v2

这是服务内部磁盘记录，与 XPC 版本独立。文件位置、0600 权限、0700 会话目录、ACL/链接限制、网络锁和原子持久化均继承[准备记录 v1](session-preparation-v1.md)。v1 仍只表示准备文件；首次允许核心 `-t` 之前才升级为 v2。v2 不允许 TUN、系统 DNS 或正常代理进程。

## 字段与任务身份

保留 v1 的会话、归属、固定资源 ID、设置/凭据 revision 和配置摘要；`schema` 为 2、`phase` 固定为 `checking`，新增 `check`：

| 字段 | 内容 |
| --- | --- |
| `origin` | 系统启动 UUID `bootID`、服务启动时的 `groupID`、服务 `ownerUID`；结构精确匹配，组 ID 大于 1 |
| `coreSHA256` | 编译清单中固定核心的 SHA256，64 个小写十六进制字符 |
| `stage` | 下表列出的检查阶段 |
| `pid` | 可选，仅作诊断；大于 1，不作为信号目标 |
| `exitCode` | 可选，launchctl 的正常退出码或负的终止信号 |

记录上限仍为 4096 字节，不含私钥、controller secret 或完整配置。每次持久化前也走严格解码验证；未知顶层或嵌套字段、未知阶段和不符合阶段的可选字段均拒绝。任务标签固定派生为 `dev.freev6.core.<小写 session UUID>`，生产域固定为 system，记录不能指定任意任务或可执行路径。

## 持久化顺序

| 阶段 | 记录条件与随后允许的操作 |
| --- | --- |
| `registering` | 私有副本全部复验后、写 job plist 或注册之前；不允许 pid/exitCode |
| `registered` | 注册已确认；job 使用 RunAtLoad=false、KeepAlive=false，核心尚未启动 |
| `starting` | 调用 kickstart 之前；不能假设核心尚未运行，pid 可能尚未获得 |
| `started` | kickstart 已返回有效 PID，将其写入；仍没有退出结果 |
| `exited` | 已确认核心被 launchd 回收，必须包含 exitCode；移除 job 前先写入 |
| `removed` | job 已确认不存在；此时才可清理会话文件与记录。注册前中断或跨启动恢复时可没有 pid/exitCode |

20 秒核心等待超时后，按专属 job 标识执行 SIGTERM、宽限和 SIGKILL；只有确认退出并清理完成后才报告已处理的超时。命令执行、持久化或回收结果不确定时保留记录，不猜测副作用是否发生。

## 重启恢复

首先校验记录、服务归属及旧服务进程组已消失。只用 signal 0 查询历史组是否存在，绝不向历史 PID/进程组发送终止信号；当前服务的组仍存在时拒绝恢复。新的服务只能通过派生的 job 标识停止核心。

同一系统启动内：

- registering/registered：job 可以尚未注册；存在时必须处于未运行状态，先记退出状态再移除。
- starting/started：job 必须存在；按标识完成停止、记录退出、移除。任务意外消失时不能断言没有遗留进程，保留记录。
- exited：已持久化退出证据；job 可以因前次移除成功而不存在，存在时仍须确认未运行。
- removed：仅在 job 确认不存在时继续清理；意外出现的任务阻止清理。

系统启动 UUID 已改变时，旧进程不可能存活，且会话 plist 不在自动加载目录；仍须确认没有同标签 job，才标记 removed 并清理。旧组已被其他进程复用或状态查询被拒绝时，保守保留记录。

清理只接受 v1 的五个固定文件，以及 v2 的 `core-job.plist`、核心检查生成的 `cache.db`、可信暂存文件。先验证全部条目，再删除；未知文件/链接/目录保留并报错。所有会话目录清空并同步后，最后删除记录。准备专用的取消/恢复方法拒绝 v2，防止绕过任务回收。

## 当前限制

用户域实测覆盖了九个记录与副作用边界、任务意外丢失、未知文件及非零/超时失败。跨启动分支尚未经历真实重启；root、跨用户和最低系统仍待验收。v2 不记录 DNS 基线，不能清理运行会话、声称网络已恢复或授权安装器忽略未完成记录。
