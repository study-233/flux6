# P5 · macOS 桌面性能实测

## 验收结果

**720 pt 窄窗连续切页通过同口径基线。** 4 个在线状态／节点数组合的主线程显示回调 P95 三轮中位数为 **10.29–11.02 ms**。12 次窄窗采样中超过 50 ms 的间隔共 0 次。此前 SwiftUI 窄窗单次记录 P95 为 30.6 ms、超过 50 ms 有 2 次。新矩阵有真实隔离宿主、不同页面实现，以及额外的 Core Video 观察器，旧记录仅有一次留存，两组不能推断其他机器的刷新率。[旧样例与采集方法](../../../../releases/macos-validation.md)

**找到了切页时重复构建隐藏页面的开销。** 优化前的 1280 pt、28 节点离线样本中，约每 13 个 Flutter 帧就出现一个 8–14 ms 的 UI build，周期与 105 ms 切页操作相符；Raster P95 仅 1.34 ms。原先外壳每次切页创建四个新页面 widget，`IndexedStack` 保留了 State，却仍让隐藏页面参与构建。现在外壳复用节点页、首页和副页面的 widget，日志及配置仍按激活状态分页或定位，节点搜索按当前 Flutter 焦点树接受快捷键。回归测试覆盖离开页面后隐藏搜索不能抢焦点，返回后恢复查询并能继续聚焦。

## 最终宽窗补测

四列布局的尾部留白从 24 pt 调至 20 pt 后，用同一份发布页面源码重跑 1280 × 800、28 节点的在线／离线热点各一次。32 次切页的主线程 P95 分别为离线 **10.63 ms**、在线 **11.76 ms**，UI P95 为 **2.30 / 2.81 ms**，Raster P95 为 **1.49 / 1.47 ms**。两次均无超过 50 ms 的主线程回调间隔，所有切页 UI／Raster 帧均在 8.33 ms 内。该补测是单次复核，独立于上面的三轮统计。[补测原始数据与统计](final-hotspot/)

两次补测各先静置 45 秒。静置时停用两组显示探针；略过最初 5 秒，每 0.5 秒取一次主进程样本，离线／在线各有 80 个记录。离线 CPU 中位数 **0.0%**、最大 **0.4%**，RSS 中位 **169.9 MiB**、范围 **169.8–185.6 MiB**；在线 CPU 中位 **0.3%**、最大 **6.1%**，RSS 中位 **173.0 MiB**、范围 **169.4–192.4 MiB**。这 45 秒只用于短时资源基线，无法据以判断数小时运行是否存在持续增长。

两种只向验收应用自身投递的指针事件（AppKit 队列与 Quartz 定向 PID）都经页面标题栏命中产品的 `NSWindow.performDrag`，每次恰好调用一次。WindowServer 没有随合成按键移动窗体，位移为 0 pt；因此这项记录只覆盖事件路由。上方 `move` 行的数字来自实际改变原生窗口位置的 25 步独立测量。[原始手势结果](final-hotspot/raw/r1-1280-28-on.json)

另用 macOS 桌面工具直接选定独立 QA 应用。现场确认前台、可见窗口 ID 7431，初始原点为 (140, 284) pt。针对页面标题空白区拖动后，探针记录 1 次原生 `performDrag` 调用，窗口实际位移 (0, 0) pt；结束时成功恢复指针。三种定向输入都能到达原生方法，但现有样本无法区分桌面输入工具的限制和产品在实体鼠标下的拖窗表现。**实际鼠标／触控板拖窗仍待手工验收**。这次等待用户动作的记录单独存档，未并入上述性能统计。[专用窗口原始结果](physical-drag/raw/r1-920-3-off.json)

## 样本和计时

本机为 Apple M5 Pro、48 GiB 内存，运行 macOS 27.0.1 (26A434)、Flutter 3.47.6 / Dart 3.13.5 的 arm64 AOT Release。内置 Retina 屏幕的逻辑分辨率为 1512 × 982 pt、缩放 2×、最高 120 Hz，对应单帧预算约 8.33 ms。JSON 保存每个进程的可见性、实际内容区尺寸、初始热状态与低电量模式。

每项矩阵使用全新进程启动。三个内容区分别为 720 × 480、920 × 620 和 1280 × 800 pt。每种尺寸都测试离线和在线、3 和 28 个节点，轮换次序重复三轮，每个版本共有 36 个进程。节点数由宿主快照断言，28 项取自产品的 WARP 节点名称表。所有操作进入产品 `HostApplication` 与 `LiveModel`，正式页面、主题、布局、日志分页和选择命令均参与运行。连接只启动独立验收包的私有子进程，本机网络、代理、DNS、TUN 和守护进程没有参与。

每次启动依次执行下列操作。

1. 等待宿主给出目标状态、节点快照，并完成实际产品窗口首轮绘制。`launchReadyMs` 从创建进程到满足全部条件，同时包括在线时建立隔离会话的时间。
2. `first4` 依次从首页访问节点、配置、日志、首页。`nav32` 随后用相同顺序和约 105 ms 间隔切换 32 次。首次是本进程首次访问页面；两组操作之间等待过渡结束。框架保留已建页面，首次访问不等同于从磁盘加载新程序。
3. `resize` 在真实 NSWindow 上执行 25 个窗口尺寸变化，宽度增大至 +80 pt 后回到起点。`move` 在真实 WindowServer 窗口上执行 25 次位移，横向往返约 ±48 pt，纵向改变约 ±16 pt，并断言实际位置发生变化。此组为可复现的原生窗体位移，不含物理鼠标跟随误差。
4. `actions` 经正常页面状态模型以约 9 ms 间隔提交 12 次节点选择。最终一次须经在线子进程或离线偏好写入确认，结束前确认宿主回到空闲状态。

三个时间源分别记录，无交叉相减。

- `mainUs` 是当前窗口 `NSView.displayLink` 在 `.main/.common` 的回调实际到达间隔，使用 `CACurrentMediaTime`。与旧 SwiftUI 采样同口径，可比较切页时主线程喂给显示回调的间隔。它还受系统调度与屏幕刷新策略影响。
- `cvUs` 是绑定该屏幕的 `CVDisplayLink` 在高优先级线程上的实际回调间隔。同时采两组数据能区分主线程阻塞和全屏显示节奏变化。二者均未测量每帧呈现到屏幕的时间。
- `frameUs` 每项为 Flutter 帧序号、UI build、Raster 和从 vsync 到 raster 完成的总跨度，单位均为微秒。通过引擎 frame number 匹配阶段，结束后留 1.3 秒接收批量发布的 `FrameTiming`。窗口仅改变位置时，静态 Flutter 页面可直接由系统合成，无 Flutter 新帧的单元格留空。
- 百分位沿用旧探针的 `floor((N−1)×p)` 索引，三轮中位值取每轮独立 P95 的中位数。超过 50 ms 按严格大于统计。UI 和 Raster 各自按 8.33 ms 预算统计超时比例，显示回调中的偶发小抖动不能当成丢帧率。

## 重跑与数据

在仓库根目录运行。需要已准备的本机 Flutter SDK、构建缓存和独立 Integration.app。首次可通过 `scripts/macos/build-flutter-host.sh` 生成该验收包。

```sh
bash scripts/macos/probe-flutter-perf.sh build
bash scripts/macos/probe-flutter-perf.sh --out build/flutter-perf/recheck
python3 scripts/macos/report-flutter-perf.py build/flutter-perf/recheck
```

探针将产品源码复制到 `build/flutter-perf` 独立编译，为单独 QA 身份加入采样方法和 3/28 节点输入，复制实际 worker 与隔离子进程并重新签名验证。`--widths 720 --counts 28 --states 0 1 --rounds 3` 可重跑指定组合。启动前应退出录屏并避免同时编译。`--steady-seconds 60` 可另外保留稳定展示期间每半秒一次的进程 CPU、RSS 与区间起止时间。进程 CPU 样本为 `ps` 的短时估值，RSS 不含独立子进程。

[`before/`](before/) 保存改动前全部 36 组，JSON 包含每个回调及每个 Flutter 帧的原始耗时。[`machine.json`](machine.json) 记录硬件、版本、运行时段、系统负荷与探针/引擎/worker 的 SHA-256。[`raw/`](raw/)、[`runs.csv`](runs.csv) 与 [`cells.csv`](cells.csv) 分别保存最终原始样本、逐轮统计和三轮中位数。

要单独重测真实指针，可启动 `bash scripts/macos/probe-flutter-perf.sh --manual-pointer --rounds 1 --widths 920 --counts 3 --states 0 --out build/flutter-perf/manual-drag`。终端报告目标 QA 进程、窗口 ID 且确认前台后，在其标题栏空白处拖动约 40 pt。探针同时记录实际原生 `performDrag` 调用次数和窗口坐标差，并在完成后将指针恢复到测试前的位置。
