# FreeV6 Flutter 集成验收 · P2、P3、P4

[打开集成验收应用](<../../../../build/macos-ui/FreeV6 Flutter Integration.app>) · [Flutter 工程](../../../../macos/flutter_ui) · [阶段计划](../../spec/macos-flclash-ui-plan.md)

在这台 Apple Silicon Mac 上直接打开应用，阅读首次启动页里的协议与隐私政策。验收包使用单独的应用身份和数据目录。它启动 FreeV6 的 Go worker 读取、校验和写入配置，用一个独立的本机子进程回报节点、延迟和速率。界面根据进程返回的结果更新。验收包中可以主动导入本地文件或 HTTP(S) 订阅。代理流量、WARP 注册、系统服务与资源准备使用隔离环境，不会更改这台 Mac 的代理或 DNS。

| 建议操作 | 预期结果 |
|---|---|
| **断开时预选，退出重开。** 在仪表盘选「全局」，点「接入节点 → 西区」，用 ⌘Q 完全退出再打开。 | 首屏仍显示「未连接」，下次节点为西区，三段模式中全局已选中。上下行保留图标，无采样显示「—」。 |
| **连接和测速。** 点花形按钮，再进入「节点」点「整组测速」。 | 启动独立子进程并读回确认之后，西区显示「使用中」。每个节点分别返回延迟，测速不会改变选择。本月和累计读取 worker 用量账本。[仪表盘实拍](connected.jpg) · [节点实拍](nodes.jpg) |
| **验收异常状态。** 从macOS 菜单栏「连接 → 隔离验收场景」选择在线零速率、等待恢复、其他用户占用或拒绝下一次控制写入。 | 在线零速率显示 0 B/s。恢复状态可重试恢复。其他用户占用时禁止改动会话。写入被拒时保留已确认值并提示原因。「恢复正常状态」退出注入的场景。 |
| **双窗口和菜单。** 用 ⌘, 打开独立设置窗，或点左侧栏底部的「设置」。分别在设置和主窗更改规则，再从系统菜单看当前模式。 | 各窗口读取同一 Swift 协调器；规则草稿按窗口保留，同一字段的冲突会留下输入。设置窗有自己的侧栏，窄窗可收起或展开。[设置窗实拍](settings.jpg) |
| **配置。** 在「域名与网段」输入错误规则并保存，然后修正。点「检查连接配置」。在「链式代理」中选「导入文件」，使用[六节点测试 YAML](../../../../shared/fixtures/chain-proxies.yaml)。 | 显示出错的字段及行号；检查配置后仍为未连接。文件由真实 worker 解析。订阅地址失败后保留输入，修改后可重试。[配置页实拍](configuration.jpg) |
| **日志。** 选择级别，暂停，执行一次连接或断开，再继续显示。可打开导出文件面板，或在确认框内清空。 | 暂停期间画面固定，恢复后可见新事件。日志首屏加载 32 条，可向前翻页；导出包含当前筛选或暂停范围内的全部记录。清空覆盖所有级别、暂停快照和已持久化的历史，随后新事件继续记录。[日志页实拍](logs.jpg) |
| **布局。** 从 macOS 菜单栏「导航 → 编辑首页布局」进入，调整顺序和宽度，也可以删除全部卡片后保存，再点「添加首页组件」。最后恢复默认。 | 自定义顺序、宽度、隐藏项和空布局在重开后保留。恢复默认后回到 FlClash 四列布局；连接卡不在视野内时，页头保留启停操作。 |

正式网络服务安装、真实隧道与系统代理/DNS 恢复、实际 WARP 注册、Sparkle 安装升级和 Intel 机器兼容性由后续发行阶段验收。本轮在原生宿主提供相应操作入口，并单独记录隔离验证范围。

构建时从仓库根目录运行 `bash scripts/macos/build-flutter-host.sh`。项目使用 Flutter 3.47.6、macOS 14+ 目标，需要 Xcode 和 Go；若 Go 不在 PATH，可设置 `GO_BIN` 指向其可执行文件。构建脚本校验 Flutter 框架、worker、隔离子进程、应用签名和权限。

## 实测记录

- [Flutter 测试](../../../../build/macos-ui/flutter-integration-tests.log)覆盖速率事件与全窗分离、旧回复和旧会话、连续选节点、测速点击不误选、配置行错、订阅失败后重试、设置快捷键及日志分页。
- [原生全量回归](../../../../build/macos-ui/flutter-host-full-tests.log)与[原生分页用例](../../../../macos/Tests/FreeV6HostTests/HostLogPagesTests.swift)覆盖 worker、配置兼容、服务与恢复、真实本机 HTTP 订阅及日志清空。[独立签名沙盒的日志验证](../../../../build/macos-ui/flutter-sandbox-journal.log)同时检查了符号链接保护。
- [实际双进程启动记录](../../../../build/flutter-toolchain/native-qa-smoke.log)覆盖独立设置窗、菜单和正常退出，再次启动时校验模式、节点和新日志持久化。两次进程都正常退出。可用[集成烟测脚本](../../../../scripts/macos/probe-flutter-host.sh)在一次性 QA 身份中复跑。

应用使用固定的 FlClash v0.9.3 / Prism UI 组件，节点页接入上游 ProxyCard 的布局与选中标记。宿主采用版本化 MethodChannel 和 EventChannel，命令带请求 ID、会话 ID、会话修订、控制令牌及配置修订。日志游标失效后从新批次读取。配置和日志显示来自本机 worker 和 Swift 会话；系统服务切换、发行安装与性能基准仍按原计划分阶段验证。
