## 1. 什么算完成

- 打开真实的 Mac 应用，在默认宽窗第一眼看到 FlClash 的固定左侧栏、半宽连接主卡、蓝色花形启停按钮、各自带曲线的上传与下载卡，以及独立的模式条。窄窗按原版网格换行。
- 界面能真正操作 FreeV6。断开时仍可选规则、全局、直连，可浏览和预选已知节点；重开保留偏好，重连后以当前会话确认结果显示「使用中」。全应用只有一套真实的网络状态。
- 首页、节点、配置、日志、设置、首次准备和恢复均可用。标题与会话入口固定；窗口变窄仍能切页；快捷键、菜单栏、日志清空和既有布局偏好均有验证记录。
- 分两次交付可双击的包。先交带原组件和模拟会话的**隔离预览**验收长相与手感，再交完成原生桥、迁移和发布验证的**本地 Release 候选包**。公开发布属于单独的发布动作。

## 3. 工程结构和职责

| 层 | 计划位置 | 职责 |
|---|---|---|
| Flutter 应用与原始组件 | 新建 `macos/flutter_ui/`；Dart 侧分为上游组件适配、页面、状态接口和夹具 | 渲染全部用户界面；管理路由、焦点、局部动画、表单草稿和布局编辑。数据通过同一接口切换模拟与真实来源。 |
| AppKit 宿主与平台通道 | Flutter 工程的 `macos/Runner`，使用本地 Swift 包公开一层最小宿主接口 | 承载 FlutterViewController，管理主窗、独立设置窗、系统菜单、菜单栏图标、文件面板、系统授权及应用退出。保持一个应用级会话所有者。 |
| FreeV6 业务与平台能力 | 已有 FreeV6Desktop、FreeV6Business、FreeV6Configuration、FreeV6System 与更新模块 | 负责服务健康、配置校验、账户、日志、偏好、网络会话、代理／DNS 恢复、worker 与系统服务通信。命令授权和结果由这层判定。 |
| 安装与分发 | 调整现有 build-app、build-ui-fixture、更新包和发行探针 | 组合 Flutter Release runner、框架、资产和现有 helper，维持正式包身份与更新链。预览使用独立的应用 ID 和目录。 |

现有 AppModel 位于 Swift 可执行目标，且部分动作依赖 SwiftUI 场景。先抽出不依赖视图的会话协调器与宿主命令接口，作为 Runner 可以导入的 Swift 包产品，再分别接 Flutter 命令和原生菜单。Swift 继续持有业务真值；Flutter 只保存展示状态、输入中的内容和请求进行态。主窗口关闭后的会话续期、菜单栏控制及退出恢复属于宿主生命周期。设置窗口按需创建 Flutter 内容并共享同一个协调器；关闭设置窗释放订阅，不重复启动 worker、测速或网络会话。[当前 AppModel](../../../macos/Sources/FreeV6App/AppModel.swift) · [现有窗口与退出流程](../../../macos/Sources/FreeV6App/FreeV6App.swift)

### Flutter 与 Swift 的接口

使用有版本的类型化平台通道，优先以 Pigeon 生成 Dart/Swift 两侧命令及回调。回调按状态、速率、日志分类；先验证工具链兼容性，保留可单独测试的协议定义。[Flutter 平台通道](https://docs.flutter.dev/platform-integration/platform-channels)

| 接口面 | 具体契约 |
|---|---|
| 窗口初始化与重同步 | 订阅时取得带版本的初始快照，包含会话阶段、拥有者可执行的动作、当前／下次模式和节点、配置版本与用量。用握手游标处理“读取快照期间收到事件”的竞态。窗口重开、休眠恢复或事件断档后重新读取。 |
| 命令 | 连接、断开、重试恢复、改模式、选节点、恢复自动、测速、保存配置、清空日志分别有显式接口。带请求 ID 和适用的会话 ID／配置修订；Swift 串行校验并去重。返回成功、失败或冲突；UI 以最终读回为准，迟到的旧回包不覆盖更新的选择。 |
| 状态与速率 | 区分 unknown、idle、connecting、running、disconnecting、recovering、occupied。速率按会话、时间戳和采样序号推送，使用有界历史，不触发根 widget 重建。高频数据可合并，关键状态转换、错误与清空事件不能被丢掉。 |
| 日志与配置 | 日志初次分页、之后按游标增量，清空返回新的截点。配置以版本提交，冲突保留输入并提示重新载入。配置、导入或账户页面确实需要的字段经过专用接口；常规事件、错误与日志中不传订阅密钥、凭据或完整敏感配置。 |
| 平台动作与多入口 | 文件选择、导出位置、系统授权、菜单快捷键、更新和登录启动交给宿主；主窗口与系统菜单调用同一命令处理器。窗体失焦或销毁后取消该窗订阅，恢复网络职责不随 widget 销毁。 |

先用模拟实现跑 Dart 界面和协议测试，再接隔离 worker 与内存会话测试 Swift 通道，最后在正式候选包中验证获授权的真实服务路径。Flutter 进程不直接启动第二个内核或写系统网络设置。

## 4. 页面和交互规格

| 页面或场景 | 最终表现与行为 |
|---|---|
| 窗口与侧栏 | 使用原版 220 逻辑像素的展开栏、48 的基础收起栏（macOS 为红黄绿按钮预留 78）、选中竖条和行底色。目的地为仪表盘、节点、配置、日志；设置由菜单或快捷键进入独立窗口。保留 macOS 窗口控件，固定页头和导航，仅正文滚动。首页主卡可见时减弱右上角的重复启停；滚出视野、被隐藏或切到别页后，右上固定位置仍能连接／断开，状态文字可读。 |
| 首页首行 | 四列网格按 **2 : 1 : 1** 排列。连接主卡左上是状态，主值是当前或下次节点，右侧用原蓝色花形启停键。上传、下载各占一张卡，展示方向、当前值、有效样本的峰值与贴底曲线。卡中的累计数字注明计数口径；数据缺失不展示假值。 |
| 首页第二行 | 左半为「规则 / 全局 / 直连」独立模式条。右半的两个短卡与原图开关位置对齐，分别是可点击的「接入节点」「当前配置」。打开真实选择器或配置详情，不模拟 FreeV6 未提供的独立 TUN／系统代理开关。 |
| 用量与下半屏 | 用同一表面与分段控件展示「本月 / 累计」，大数字直接显示总量，下方拆分上传、下载。去掉重复的年份和「累计用量」小字。宽高充足时可用原图下部左宽右窄结构显示最近应用事件和节点摘要；高度不足时优先摘要。 |
| 节点 | 来源、组名、节点名、预选／使用中、延迟各自有固定位置。提供搜索、单项测速、整组测速、定位已选和恢复自动。少量节点直接展示，长名称和 28 节点列表可滚动。测速有独立点击目标，键盘可搜索、选择、提交和退出。主卡、节点页、系统菜单使用同一节点目录。 |
| 配置与设置 | 配置页保留文件／订阅导入、代理规则、链式／备用配置、校验、保存、取消及具体行错；WARP 账户与服务维护保留原能力。设置内容使用 Flutter 表单，独立窗口内有自己的左侧栏、标题栏开关与选中项。主窗和设置窗的未保存草稿分别处理，640×440 的设置窗口也能收放侧栏并访问所有分类。 |
| 日志与诊断 | 紧凑行，固定筛选、暂停／继续、导出、「清空…」。清空需确认全部级别、暂停快照和本机应用历史的范围；已导出的文件及系统日志独立。新记录继续写入，旧游标不会让已清空的行重现。读写失败给就地重试。 |
| 首次使用与异常 | 首次阅读、服务准备、资源缺失、安装／恢复失败、公告与更新均有入口。正确区分「准备服务」「连接」「重试恢复」；occupied 状态显示占用原因，不允许操作他人的运行会话。切页后保留搜索、滚动位置和未提交表单。 |

**响应布局。** 按扣除实际侧栏及文字缩放后的正文可用宽度决定列数。上游桌面断点为 860，低于该值切为双列；其密度策略将小于 640 的内容视为移动密度。FreeV6 主窗最小 720×480，窄窗默认收起侧栏，维持桌面交互。若用户手动展开导致正文极窄，切为单列可滚动卡片、仍用桌面导航。920×620 测收起与展开两种状态；在更宽的窗口验证展开侧栏下的完整四列。双列顺序为整宽连接卡、两张速率卡、整宽模式、节点与配置、用量。标准桌面卡片圆角 32，标准内边距横 22 / 纵 20，紧凑横 20 / 纵 16；首行标准／紧凑高 208 / 176，控制行 64 / 56。字号放大或长中文时优先确保内容可读。[上游布局](https://github.com/chen08209/FlClash/blob/be84736605527034689c95bf27828ff27d912c5e/lib/views/dashboard/layout.dart) · [桌面排列](https://github.com/chen08209/FlClash/blob/be84736605527034689c95bf27828ff27d912c5e/lib/views/dashboard/dashboard.dart#L133-L268)

**动效。** 保留原件各自动作的节奏，例如连接形状变化约 450 ms、侧栏展开 250 ms、选择指示约 320 ms。命令发出立即显示按下或进行中，不等动画结束才执行，也不把动画结束当作服务成功。连续改选可打断上次动作；启用减少动态效果时以明暗、文字和焦点表示状态。图表采样只重绘各自区域。[连接键实现](https://github.com/chen08209/FlClash/blob/be84736605527034689c95bf27828ff27d912c5e/lib/views/dashboard/widgets/current_outbound.dart#L695-L735) · [侧栏时序](https://github.com/chen08209/prism_ui/blob/63450c0ac0e8e1b2c0f3ed4ad7926dc94e083185/lib/sidebar.dart#L23-L32)

### 会话状态验收样例

| 给定情形 | 用户动作 | 界面通过条件 |
|---|---|---|
| 未连接，有本地节点 | 选全局、西区，退出重开 | 显示「未连接 / 下次使用西区」，全局选中，上下行图标与基线始终可见，无样本显示「—」。 |
| 重新连接或节点组已变化 | 点花形连接键 | 等待真实服务确认。西区存在且应用成功才显示「使用中」；已移除或写入失败时显示实际节点和可解释的提示。 |
| 在线但无流量 | 查看速度、切本月／累计 | 有效零值显示「0 B/s」，缺失采样不补零；月度和累计分别来自对应报告。 |
| 快速换模式、节点或会话 | 先点 A 再点 B，A 的结果较晚返回 | B 不被旧回包覆盖。若当前模式已切换而下次默认保存失败，分别说明实际和下次值。 |
| 正在恢复／他人占用 | 点击模式或连接入口 | 原生能力决定操作是否可用；不冒充离线、不中断他人连接，恢复失败提供正确的重试及诊断入口。 |

## 5. 升级、布局和回退

1. **状态所有权。** 模式默认值、节点偏好、配置修订、用量报告和日志仍由原生持久化层读取。Flutter 路由、侧栏折叠和局部展示偏好可以独立保存。预览使用独立 bundle ID、目录与模拟服务，不申请正式网络授权。
2. **原有布局。** 现有 v1 包含 connection、mode、node、usage、speed 五种逻辑组件。优先沿用 v1 表示，speed 显示为一组上下行卡，一起移动、显示或隐藏；原有自定义顺序、宽窄与空布局都保留。首次无偏好或用户点「恢复默认」时启用官方式排序。原版桌面默认布局与 FreeV6 自定义布局分别拍图验收；不会在升级时自动覆盖用户的布局。[当前布局格式](../../../macos/Sources/FreeV6Desktop/DashboardLayout.swift)
3. **配置与编辑。** 旧配置直接经现有 worker 解码；载入与保存带版本，模式或节点的快捷修改不能覆盖规则草稿。发生冲突时重新取快照，保留用户输入。只在新格式确有需要时引入版本化迁移，迁移先读后写、原子提交、可重复运行，并保留旧版本可读副本。
4. **切换顺序。** 第一阶段保留旧预览作为行为对照，新预览独立安装。主窗、设置窗、菜单和退出路径都完成后才替换正式入口。候选包有问题时停止晋级，恢复上一个已验证的客户端；回退前按现有流程断开并确认代理／DNS 已恢复，核对已有配置、密钥和日志仍可读取。系统 helper 版本、身份或协议改变时单独验证兼容与恢复。

## 8. 哪些问题会影响切换

| 风险 | 处理与判断 |
|---|---|
| 原件依赖 FlClash 私有 provider、生成代码或插件 | P0 列出传递依赖；保留视觉子树和动画，将业务读写抽成注入接口。任何外观偏差都标明在哪个上游文件做了什么改动，不以默认 Flutter 控件悄悄替换。 |
| 双窗口、菜单栏和网络事件相互覆盖 | 同一协调器处理命令；窗口订阅独立释放。增加关闭主窗、通过菜单断开、再打开主窗的用例，确保状态可重建。 |
| 视觉相同但真实操作仍卡顿 | 分别记录 Flutter UI／Raster 帧与原生回调；单独开关采样、节点列表、日志增量，定位重绘或桥接频率。每次修复复跑相同样例。 |
| 新 Runner 能启动但安装器、更新或恢复失效 | 在替换正式入口前，用隔离候选包验证签名身份、helper 握手、更新、升级、回退及网络恢复。 |
| 来源材料不可长期复建或发布条件不清 | 所用源文件、锁定提交、补丁和资产清单进入可复建工程，以原版可获取的固定来源为准；1.2 MB 本地参考 ZIP 只作查阅。发布流程缺少对应源码、许可、资源授权或目标机证据时，保持本地候选状态。 |

**如何跟进。** P1 首先看实际可操作界面与原图是否一致，尤其是花形按钮、侧栏切换和两张速率卡。P3 再验「断开选全局和西区 → 退出重开 → 连接 → 服务确认西区」。P6 才判断是否具备发行条件。三个节点分别回答外观、业务和分发问题，每次都有明确的可打开产物或测试记录。
