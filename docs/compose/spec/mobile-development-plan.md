# FreeV6 手机版开发计划

日期：2026-11-10。已确认顺序：Android 优先，随后 iOS。实现路线按用户提出的 FlClash 参考调整为：以 FlClash Android 源码为基础二次开发，沿用其手机版界面、交互和运行框架，接入 FreeV6 业务。当前阶段为开发规划，上游版本与工期在基线编译验证后锁定。

首个目标是在 Android 真机上完成“校园 Wi-Fi 环境检查 → WARP 凭据准备 → VPN 授权 → 实际连接 → 节点切换 → 断开恢复”的完整流程。先构建并运行固定版本的 FlClash，再加入 FreeV6 的 WARP 自动配置、校园规则、网络检查和品牌内容。Android 首期交付签名 APK 内测包，iOS 后续单独验证 Network Extension 与分发条件。

[FlClash 上游](https://github.com/chen08209/FlClash) 已提供 Android 客户端、mihomo、节点测速、配置和手机自适应布局；其 [核心桥接](https://github.com/chen08209/FlClash/blob/main/core/lib.go) 已有接收 TUN 文件描述符的 `StartTun` 接口。上述能力作为复用基础；具体固定版本的 MASQUE 能力和 FreeV6 配置兼容性仍需真机验证。

## 现有基础与复用边界

| 现有模块 | 手机版处理方式 |
| --- | --- |
| FlClash 上游 Android 工程、Flutter 页面与核心桥接 | 作为手机端基础，保留原版导航、组件、动画、节点页、设置和 VPN 生命周期；集中修改 FreeV6 业务差异。 |
| `apps/macos/flutter_ui/lib` | 参考既有 FreeV6 文案和状态语义；手机版直接采用上游手机实现，不从 Mac 窗口和主题反向改造。当前上游组件固定版本见 `vendor/UPSTREAM.json`，手机基线另行锁定。 |
| `internal/warp/` | 复用注册、凭据解析和校验；凭据持久化由 Android Keystore 或 iOS Keychain 适配层负责。 |
| `internal/app/`、`internal/mihomo/` | 复用业务配置、节点、规则解析和校验，拆开平台网络配置。当前生成器仅接受 Windows/macOS，不能直接用于手机。 |
| `internal/worker/` | 复用业务方法和数据一致性设计，将依赖 stdio、桌面资源包和目录的逻辑隔离；不直接把整个 worker 当作手机版后台进程。 |
| `shared/fixtures/`、`shared/protocol/` | 复用合成样本、配置修订与状态同步语义；新增移动端接口契约。 |
| macOS XPC、launchd、管理员服务与桌面系统代理 | Android 沿用 FlClash 的 VPN 实现；iOS 后续实现 Packet Tunnel Extension。 |

FreeV6 当前配置使用 **WARP over MASQUE**，桌面核心清单固定为 mihomo v1.19.31，资产仅包含 Windows/macOS。手机版优先使用 FlClash 的核心构建链，在 P0 核对其协议支持、P2 验证完整 FreeV6 链路；不要求照搬桌面核心版本。代码依据见 [配置生成器](../../../internal/mihomo/config.go) 和 [核心清单](../../../internal/mihomo/runtime-assets.json)。

## 首版范围

建议以 Android 10 及以上、arm64 真机为第一批验证目标，P0 根据 Flutter、NDK 与核心实际兼容性确认最低版本；编译与目标 API 在开工时锁定受支持版本。首要使用场景是具有可用 IPv6 的校园 Wi-Fi。

以下为 FreeV6 首版必须验收的范围。上游已有的订阅、分应用代理等功能可先保留，逐项检查与 FreeV6 配置的兼容性；不为了缩小首版清单而大规模删改上游实现。未经验证的入口不对用户承诺支持。

| 首版必须交付 | 后续迭代 |
| --- | --- |
| 首次引导、网络检查、VPN 授权及取消处理 | iOS 客户端 |
| WARP 凭据自动准备、安全保存、失效与重试处理 | 链式代理、备用校园配置及完整订阅管理 |
| 一键连接/断开、真实状态与错误说明 | 按应用分流、快捷设置磁贴、桌面小组件 |
| 接入点列表、延迟测试、手动选择 | Always-on VPN、开机自动连接及阻止非 VPN 流量模式 |
| 规则/全局模式、校园认证地址及网段绕过 | 桌面全部高级配置与布局定制 |
| 实时上下行、会话用量、脱敏诊断日志 | 跨端同步、商业应用商店发布 |
| 前台服务通知、锁屏运行、网络变化处理 | 热点共享及平板专属布局 |
| 签名 APK、覆盖安装验证、构建说明与源代码材料 | 更广设备和架构支持 |

首版默认不主动把隧道从校园 Wi-Fi 切到蜂窝网络。Wi-Fi 丢失后停止重连并提示网络变化；这不等于阻止 Android 或其他应用使用蜂窝流量。应用中的用量是本机隧道统计，不能表示运营商或校园网实际计费。

## 技术方案

沿用 FlClash 的 Flutter 状态管理、配置管线、原生 VPN 服务与核心调用链，将 FreeV6 接成业务适配模块。复用现有 Go 的 WARP 注册和配置生成逻辑，通过上游已有 Go 桥接暴露必要方法，避免再建立一套并行的 worker 或 VPN 控制通道。Flutter 页面关闭或重建后，从实际服务恢复连接状态。

### Android

- 优先直接复用 FlClash 的 Android VPN 服务、授权、TUN、通知与核心桥接；P0 验证原版构建和运行，只有确认存在能力缺口时才做局部修改。
- 验证核心接入系统 TUN 文件描述符，以及隧道、DNS 和直连出站套接字的 `protect()`/底层网络绑定，防止流量再次进入自身 VPN。系统负责路由和 TUN 的建立，移动端配置不沿用桌面的自动路由写入方式。
- 在 FlClash 配置管线中增加 FreeV6 配置源，自动生成 WARP 接入点与校园规则。核对上游覆盖设置不会改写所需 IPv6、DNS、MTU 与出口语义；校园域名绕过同时验证 DNS 和核心规则。
- 复用上游启停、节点选择、模式和流量接口；只为 FreeV6 凭据准备与网络检查补充状态。核对重复请求、取消和旧事件不会覆盖新会话，不另建重复状态系统。
- WARP 私钥等敏感数据使用 Keystore 保护的加密存储；日志、导出、备份和崩溃信息不包含凭据或带认证参数的 URL。
- 核心随 APK 更新；规则数据可独立下载并校验，准备失败保持原有有效数据。配置更新使用版本检查和原子提交。

Android 官方 VPN 接口提供 TUN、用户授权、套接字保护及服务生命周期，运行服务需按目标系统处理前台要求。[Android VPN 开发说明](https://developer.android.com/develop/connectivity/vpn)。Android 对应用可写目录中的可执行文件有限制，因此本计划选择随 APK 打包核心的路线。[Android 执行权限说明](https://developer.android.com/about/versions/10/behavior-changes-10#execute-permission)。

### iOS

Flutter 复用业务页面；Swift 使用 `NETunnelProviderManager` 管理配置，`NEPacketTunnelProvider` 扩展承担数据转发。共享 Go 业务层与核心是否能以适合扩展的形式构建，必须先做真机验证，并测量内存、启动耗时和后台恢复；不预先承诺 Android 原生适配代码可直接复用。App 与扩展的配置共享、密钥访问和状态同步分别设计。[Apple Packet Tunnel 说明](https://developer.apple.com/documentation/networkextension/packet-tunnel-provider)。

FlClash 当前上游支持列表包含 Android、Windows、macOS 和 Linux，不能据此视为已有 iOS 客户端。Android 内测后单独开展 iOS 核心构建、开发账号、签名与 Network Extension 验证。若选择 App Store 分发，需要按当时规则确认组织账号等 VPN 发布条件；分发审核时间不计入开发估算。[FlClash 平台列表](https://github.com/chen08209/FlClash#download) · [Apple VPN 应用审核条款](https://developer.apple.com/app-store/review/guidelines/#vpn-apps)。

## 手机界面

直接采用固定版本 FlClash 的手机版页面、导航、连接按钮、流量卡片、节点列表、弹层、动画和深浅色。以原版 Android 真机截图为对照，仅调整 FreeV6 名称、图标、文案与业务入口；保留原版页面结构。新增 WARP 凭据和校园绕过设置时使用上游同类控件与交互。

- 首页突出连接按钮、实际网络状态、当前节点、实时速率和会话用量；高级选项逐层展开。
- 首次连接依次解释网络条件、准备凭据与规则、申请系统 VPN 授权；每一步提供取消和针对当前失败的重试。
- 状态至少区分未连接、等待授权、准备中、连接中、已连接、网络变化、断开中和失败。只在转发与出口检查成功后显示已连接；节点测速成功不能替代出口检查。
- 适配小屏、安全区、软键盘、系统返回手势、深浅色和大字体；Android 主要操作触控区域以至少 48 逻辑像素为设计目标。
- 无采样显示“—”，有效零值显示“0 B/s”；状态同时使用文字，避免仅靠颜色表达。后台停止界面动画与高频刷新。

界面验收以选定 FlClash 版本的原件为准，通用移动端可访问性要求用于检查新增业务控件。

## 实施阶段与验收

按复用上游的差异工作安排，P0 完成后给出估算。原先独立建立移动工程的 4–7 周估算不再作为当前排期。

| 阶段 | 工作与交付物 | 通过条件 |
| --- | --- | --- |
| P0 跑通上游 | 固定 FlClash、核心和子模块提交，按上游方式构建 Android；核对 MASQUE 能力、构建依赖与许可材料。 | 原版 APK 可重复构建并在 arm64 真机启动，用受控配置验证 VPN 启停；记录 FreeV6 接入点与差异清单。 |
| P1 FreeV6 外观 | 使用原版手机页面，替换品牌与文案，加入 WARP 和校园设置入口，使用独立应用标识及数据目录。 | 交付可安装的界面预览 APK；主要页面、动画与原版对照一致，尚未接入的业务操作明确标记。 |
| P2 接入业务 | 复用 Go WARP 注册和配置生成，接入上游配置管线、凭据存储、校园绕过及出口检查。 | 从干净安装到授权、MASQUE 实际转发、切换节点和断开恢复完整通过；交付功能内测 APK。 |
| P3 适配与稳定性 | 验证网络变化、锁屏、省电、权限撤销、核心退出、配置覆盖及已有高级功能兼容性；测量耗电与内存。 | 完成下列真机矩阵并修复阻断项，明确保留功能的验证范围。 |
| P4 Android 内测发布 | Release 签名、覆盖安装、许可与对应源码材料、安装指南和已知问题。 | 安装和升级通过；包可追溯到上游及 FreeV6 改动，Release 无调试接口。 |
| P5 iOS | 先验证核心与 Packet Tunnel 扩展，再复用 Flutter 页面完成 iPhone 适配。 | 真机实际连接、后台、切网和断开通过；按账号条件交付开发签名或测试分发包。 |

首个可见交付是 P1 的 FlClash 风格 FreeV6 APK，首个真实连接版本是 P2。工期重点由 FreeV6 业务接入与真机验证决定；上游已有功能按复用和回归工作估算。

## 真机验证标准

1. **真实网络：** 至少覆盖目标校园 IPv6 Wi-Fi、普通双栈 Wi-Fi、IPv4-only 网络、无网络和蜂窝网络。验证 IPv4/IPv6、TCP/UDP、DNS、校园认证页面与选定规则的实际出口；不满足条件时给出明确状态。网络可达与计费结果分别记录，“免流”效果需目标校园的实际计费证据。
2. **状态与恢复：** 连续至少 20 次启停、连接中取消、快速切节点/模式、其他 VPN 接管、系统撤销授权、核心异常及应用界面重建。每次核对服务、UI 与通知状态，断开后正常联网且无遗留 TUN 资源。
3. **后台：** 在原生 Android 设备和至少一种国内厂商设备上分别进行 30 分钟锁屏、至少 2 小时混合前后台运行。覆盖省电与系统回收；正常返回时恢复真实状态，强制停止后重开不会假报连接。Always-on 未完成前不宣称支持。
4. **性能：** 使用 Release/Profile 构建记录冷启动、核心启动、连接耗时、内存峰值、空闲与传输耗电。P0 建立相同设备和网络下的上游基线，P3 比较；不事先承诺未经测量的耗电百分比。
5. **数据与发布：** 凭据损坏、密钥失效、规则下载中断、升级迁移和导出脱敏均有验证；Go 业务测试、Flutter 状态/交互测试、Android 服务集成测试与受影响桌面回归通过。模拟器主要用于 UI 和故障注入，校园网络结论来自真机。

## 建议目录与开工顺序

建议在 `apps/android` 保存固定版本的 FlClash 派生工程及来源清单，尽量保持上游目录结构；在其业务层集中放置 FreeV6 适配。`scripts/android/` 保存构建和验收脚本，合成样本继续放在 `shared/`。记录上游提交、核心/子模块版本及本地修改，便于后续同步修复；公共 Dart 包只在出现实际共享需要时提取。

下一次进入开发先执行 P0：构建原版 FlClash Android，确认真机运行、核心能力和 FreeV6 配置接入位置，再按差异清单估算工期。现有工作区包含大量桌面开发中的改动，应先记录其基线；手机工程独立接入，公共 Go 代码变动配套桌面回归。

FlClash 派生客户端保留 GPL 许可、上游署名和修改记录，并配套交付对应源码；具体组件材料以 [THIRD-PARTY.txt](../../../THIRD-PARTY.txt) 和选定上游版本为依据，在 P0 核对、P4 随发布验证。
